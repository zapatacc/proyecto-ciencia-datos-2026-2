# Syllabus — Proyecto en Ciencia de Datos

Este documento complementa la [`guia-de-aprendizaje.md`](guia-de-aprendizaje.md), que es el mapa principal que se socializa con el estudiantado en la primera clase.

## Propósito

El curso desarrolla la capacidad de convertir una solución de ciencia de datos en un sistema que otras personas puedan ejecutar, consumir, verificar y mantener. El foco no es entrenar muchos modelos: es integrar código, datos, modelo, servicio y despliegue con evidencia reproducible.

## Resultados esperados

Al finalizar, el estudiantado podrá:

- usar Git y ambientes aislados para colaborar de forma reproducible;
- explicar cómo se comunican aplicaciones mediante HTTP y JSON;
- exponer una predicción con FastAPI y consumirla desde Streamlit;
- rastrear experimentos y versiones de modelos con MLflow y Databricks;
- contenerizar y conectar servicios con Docker y Compose;
- publicar una aplicación accesible y explicar infraestructura básica de nube;
- consultar logs, identificar versiones y realizar una actualización o rollback básico.

## Módulos

1. Fundamentos para construir y compartir aplicaciones de datos.
2. Del modelo al producto: diseño y trazabilidad MLOps.
3. De local a producción: contenedores, nube y operación.

## Modalidad de trabajo

Las sesiones usan una ventana efectiva de 100 minutos: recuperación y objetivo, demostración breve, práctica guiada, verificación por pares y evidencia de salida. Habrá actividades individuales y un proyecto en equipos de dos o tres personas.

## Evaluación

| Componente | Peso |
|---|---:|
| Tareas y actividades de clase | 20 % |
| Quices | 20 % |
| Proyecto en equipo: reporte 15 % + exposición 15 % | 30 % |
| Examen final | 30 % |
| **Total** | **100 %** |

Los equipos serán de dos personas, con un máximo de tres integrantes. La política de redondeo se mantiene: decimal menor o igual a 5 baja al entero anterior; decimal mayor que 5 sube al siguiente. No se redondean hacia arriba las calificaciones menores a 6.

## Entregas y colaboración

- Todas las tareas, trabajos, actividades, quices, exámenes y entregas del proyecto se presentan exclusivamente en el espacio correspondiente de Canvas.
- No se aceptan entregas por correo, Teams, mensajes privados ni otros medios.
- Hasta una hora de retraso: calificación máxima de 8; más de una hora y hasta dos: máxima de 7; desde dos horas: revisión sin calificación.
- No se publican secretos, tokens, credenciales, IDs privados ni datos personales en Git.
- El trabajo de equipo debe conservar evidencia individual mediante commits, revisiones y explicaciones.
- Las soluciones se mantienen separadas de los starters.
- Las herramientas de nube se usan con límites de costo, mínimo privilegio y cierre verificable.

## Cuentas y contingencias

GitHub será necesario. Databricks, Hugging Face y AWS se validarán antes de sus respectivas sesiones y tendrán una alternativa local o demostrativa cuando una cuenta estudiantil no esté disponible. No se exigirá una tarjeta personal sin una política institucional explícita.
